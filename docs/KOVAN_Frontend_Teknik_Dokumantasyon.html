1. Genel Mimari ve Teknoloji Tercihleri

KOVAN frontend mimarisi, yüksek performans, modern kullanıcı deneyimi ve düşük bakım maliyeti hedeflenerek tasarlanmış tek sayfa uygulamasıdır (Single Page Application - SPA). Kat Mülkiyeti Kanunu (KMK) standartlarına tam uyumlu çalışan sistem, yönetici ve sakin rollerine göre dinamik olarak arayüz üretir.

1.1 Neden Vite ve React 19?

  • Vite Esbuild & Rollup Motoru: Klasik Create React App (Webpack) tabanlı yapılarda build ve HMR (Hot Module Replacement) saniyeler sürerken; Vite yerel ES modüllerini (native ESM) kullanarak milisaniyeler seviyesinde anlık geliştirme ve npm run build aşamasında optimize edilmiş bundle üretir.
  • React 19 Bileşen Yaşam Döngüsü: DOM güncellemelerinde sanal DOM (Virtual DOM) verimliliği ve hook mimarisi (useState, useEffect, useCallback, useMemo) ile hatasız state akışı sağlanır.
  • Tree-Shaking: Kullanılmayan ikon (Lucide-react) ve kütüphane fonksiyonları derleme aşamasında otomatik budanarak tarayıcıya gönderilen JavaScript dosya boyutu 122 kB (gzip) seviyesinde tutulmuştur.

1.2 Tasarım Sistemi ve CSS Mimarisi

Projede ağır harici UI kütüphaneleri (Bootstrap, Material UI vb.) yerine tamamen özelleştirilmiş, yüksek performanslı ve sıfır bağımlılıklı bir CSS Custom Properties (CSS Değişkenleri) sistemi kurulmuştur.

3. Bileşenler, State'ler ve Metotların Detaylı İncelemesi

3.1 `src/App.jsx` - Ana Denetleyici & State Yöneticisi

Uygulamanın omurgasıdır. React Router gibi harici bir yönlendiriciye ihtiyaç duymadan, hafif ve hızlı bir State-Driven Navigation (Durum Güdümlü Yönlendirme) mimarisi uygular.

State Değişkeni Tipi & Varsayılan Fonksiyonel Görevi
view String ('tanitim') Kullanıcının tanıtım sayfasında mı ('tanitim'), yönetim panelinde mi ('app') yoksa giriş ekranında mı ('login') olduğunu yönetir.
activeTab String ('dashboard') Panel açıkken hangi modülün (Daireler, Aidat, Talepler, Ayarlar) aktif olduğunu belirler.
currentRole String ('yonetici') Rol simülasyonunu yönetir ('yonetici' veya 'sakin'). Rol değiştikçe izin verilmeyen menüler gizlenir.

Önemli Metotlar:

  • handleViewChange(newView): Ekranlar arası geçişi sağlar. Tanıtım sayfasından panele geçişte tarayıcı scroll pozisyonunu en üste sıfırlar (window.scrollTo(0, 0)).
  • handleRoleSwitch(newRole): Mentöre rol bazlı yetkilendirmeyi göstermek için tek tıkla Yönetici ve Sakin perspektifleri arasında geçiş yapar. Sakin rolüne geçildiğinde finansal kasa detayları veya yönetici ayarları saklanır.

3.2 `src/prototype/useTheme.js` - Özel Tema Hook'u

Kullanıcının tema tercihini yöneten ve tarayıcı hafızasında (localStorage) saklayan custom hook'tur. 

// useTheme.js Çalışma Mantığı:
export function useTheme() {
  const [theme, setTheme] = useState(() => {
    return localStorage.getItem('kovan_theme') || 'dark';
  });

  useEffect(() => {
    document.documentElement.setAttribute('data-theme', theme);
    localStorage.setItem('kovan_theme', theme);
  }, [theme]);

  const toggleTheme = () => {
    setTheme(prev => (prev === 'light' ? 'dark' : 'light'));
  };

  return { theme, toggleTheme };
}
Mentöre Teknik Açıklama: "Hook içinde useState'e başlangıç değeri olarak bir fonksiyon (lazy initialization) vererek her re-render'da localStorage okuma maliyetini engelledik. useEffect ile DOM'un en tepesindeki html etiketine data-theme atayarak tüm CSS değişkenlerinin anında ve sıfır gecikmeyle değişmesini sağladık."

3.4 `src/prototype/Payments.jsx` - KMK Uyumlu Aidat & Faiz Mantığı

Kat Mülkiyeti Kanunu Madde 20 uyarınca aidat borçlarını, gecikme faizlerini ve online tahsilat akışlarını yöneten kritik modüldür.

KMK Madde 20 Gecikme Faizi Formülü:

Kanuna göre vadesinde ödenmeyen aidat borçları için aylık %5 (veya yönetim planında belirlenen oran) gecikme tazminatı işletilebilir. 

// Aidat ve Gecikme Faizi Hesaplama Fonksiyonu:
function calculateLateFee(debtAmount, dueDateStr, monthlyRatePercent = 5) {
  const dueDate = new Date(dueDateStr);
  const today = new Date();
  
  if (today <= dueDate) return 0; // Vadesi geçmemiş borçta faiz yok

  // Gecikilen gün ve ay farkı hesabı
  const diffTime = Math.abs(today - dueDate);
  const diffDays = Math.ceil(diffTime / (1000 * 60 * 60 * 24));
  const diffMonths = diffDays / 30.0;

  // Faiz = Borç * (Aylık Oran / 100) * Gecikilen Ay
  const lateFee = debtAmount * (monthlyRatePercent / 100) * diffMonths;
  return Math.round(lateFee * 100) / 100;
}

4. Mentörün Sorabileceği 16 Zorlayıcı Soru & Yanıtlar

Soru 1 Neden Redux veya Zustand gibi global bir state kütüphanesi kurmadınız?
Cevap: "Projemizin mevcut ölçeğinde global state ihtiyacı yalnızca 'Aktif Sekme', 'Oturum/Rol' ve 'Tema' gibi birkaç anahtar değerden ibarettir. React'in kendi useState ve Context API imkanları fazlasıyla yeterli ve hafiftir. İhtiyaç yokken Redux eklemek gereksiz boilerplate kod üretir, bundle boyutunu 50+ kB artırır ve bakımı zorlaştırır. Gelecekte soket tabanlı canlı mesajlaşma ve bildirim katmanı genişlediğinde Zustand gibi minimalist bir kütüphaneye kolayca evrilebilecek modülerlikte tasarladık."
Soru 2 React'te gereksiz re-render'ları (re-rendering) nasıl önlediniz?
Cevap: "Bileşenleri atomik parçalara böldük. Örneğin bir tabloda arama kutusuna harf yazıldığında tüm sayfanın yeniden render olmasını engellemek için arama state'ini ilgili yerel bileşende izole ettik. Ağır hesaplamalar (örneğin KMK faiz oranları ve toplam site aidat istatistikleri) için useMemo kullandık; olay yöneticilerinde (event handlers) ise referans stabilitesi için useCallback tercih ettik."
Soru 3 Dark Mode geçişinde sayfa ilk yüklenirken beyaz ekran patlaması (FOUC - Flash of Unstyled Content) nasıl engellendi?
Cevap: "CSS'imizi CSS-in-JS kütüphaneleri (runtime CSS) yerine doğrudan saf CSS değişkenleri (CSS Variables) üzerine inşa ettik. html[data-theme='dark'] seçicisi tarayıcı boyama yapmadan (paint phase) önce hazır hale geldiği için render engellenmez ve hiçbir flicker yaşanmaz. Kullanıcı tercihi localStorage üzerinden anında okunur."
Soru 4 CSS mimarinizde neden Tailwind veya Bootstrap yerine saf CSS değişkenleri kullandınız?
Cevap: "KOVAN'a özgü yüksek marka kimliği (kovan sarısı, petek dokusu, özel cam efektleri) gerekiyordu. Harici kütüphaneler yüzlerce kullanılmayan class yükleyerek performansı düşürür ve standart kalıplara hapseder. Saf CSS Custom Properties kullanarak hem HTML'imizi temiz tuttuk, hem tarayıcının yerel donanım hızlandırmasından (hardware acceleration) tam faydalandık, hem de runtime maliyeti sıfır olan bir tasarım sistemi elde ettik."
Soru 5 Kat Mülkiyeti Kanunu (KMK) standartlarını frontend'de nasıl modellediniz?

5. Canlı Backend Entegrasyonu, Güvenlik (#11, #42, #62), Aidat / Arsa Payı (#114) & Gereksinim Eşleştirmesi (#117)

Bu bölümde; KOVAN platformunun mock prototip aşamasından canlı Kubernetes mikroservis kümesine bağlanması sürecinde hayata geçirilen güvenlik sıkılaştırmaları, mevzuat uyumları ve mimari çözümler detaylandırılmıştır.

5.1 #11: Token Saklama, Çıkışta Sunucu Revocation ve Koruyucu Başlıklar (CSP)

Kimlik doğrulama mimarisi JWT Access Token (kısa ömürlü) ve Refresh Token (uzun ömürlü, Beni Hatırla ile 90 gün) yapısına dayanır.

  • Oturum Depolama & Kişisel Veri Güvenliği (Storage Sanitization): İstemci tarafında localStorage deposunda kovan_auth altında yalnızca teknik oturum belirteçleri (token, refreshToken, siteId, roles, permissions, workspaces) saklanır. Kullanıcının adı, soyadı, telefon numarası ve e-postası gibi hassas kişisel profil bilgileri (PII) tarayıcı diskine yazılmaz; yalnızca bellekte (React state / in-memory) tutulur ve sayfa yenilendiğinde /auth/me üzerinden güvenle çekilir.
  • Doğrudan Sunucu Bildirimi ile Çıkış (Guaranteed Logout Revocation): src/api/kovan.js içindeki logout() fonksiyonu, oturum kapatıldığında 401 yenileme interceptor döngüsüne girmeksizin doğrudan POST /auth/logout uç noktasına { refreshToken } gönderir. İstek keepalive: true bayrağıyla atıldığı için sekme kapansa bile sunucuya ulaşır; ani kapanışlar için navigator.sendBeacon yedeği mevcuttur. Çıkış anında kovan_auth, kovan_active_tab, kovan_users ve sessionStorage tamamen sıfırlanır (Full Storage Purge).
  • Kurumsal Güvenlik Başlıkları (CSP): vercel.json ve index.html dosyalarına XSS, Clickjacking ve veri sızıntılarını engelleyen kurumsal HTTP başlıkları eklenmiştir:
    • Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com data:; img-src 'self' data: https: blob:; connect-src 'self' https://kovanbe.universeconn.online https://*.vercel.app;
    • X-Content-Type-Options: nosniff (MIME sniffing engelleme)
    • X-Frame-Options: DENY (Iframe ve Clickjacking engelleme)
    • Referrer-Policy: strict-origin-when-cross-origin (Referans URL sızıntı koruması)
    • Permissions-Policy: camera=(), microphone=(), geolocation=() (Donanım kısıtlaması)
  • Mobil Güvenlik Şartnamesi: Mobil istemcide AsyncStorage yasaklanmış; iOS Keychain ve Android EncryptedSharedPreferences (expo-secure-store / react-native-keychain) zorunlu kılınmıştır.

5.2 #42: Davet Token'ının Adres Çubuğu Sanitizasyonu

Site veya daire davet bağlantıları https://.../davet?token=XYZ... şeklinde üretilir.

Adres Çubuğu Güvenlik Riski ve Çözümü: Token URL parametresinde kaldığında tarayıcı geçmişine kaydolur, ekran görüntülerinde ifşa olur ve dış sitelere tıklandığında Referer başlığıyla üçüncü taraflara sızabilir. src/App.jsx içindeki invitationTokenFromUrl() fonksiyonu geliştirilerek:
  1. Token URL'de yakalandığı anda sessionStorage'a güvenle alınır.
  2. window.history.replaceState({}, "", "/davet") çağrılarak adres çubuğundaki hassas token parametresi saniyesinde temizlenir.
  3. Kullanıcı sayfayı yenilese (F5) dahi davet sessionStorage'dan geri yüklenir; işlem tamamlanınca hafıza silinir.

5.3 #62: CSRF Güvenlik Politikası ve Double Submit Cookie Mimarisi

İleride token'lar XSS güvenliğini artırmak için HttpOnly çerezlere taşındığında, tarayıcıların çapraz isteklerde çerezleri otomatik göndermesinden kaynaklanan CSRF (Cross-Site Request Forgery) riski doğacaktır.

  • Double Submit Cookie Çözümü: src/api/client.js içerisine getCsrfToken() fonksiyonu eklendi. Tarayıcıdaki XSRF-TOKEN / CSRF-TOKEN çerezi okunur.
  • Otomatik Başlık Ekleme: Durum değiştiren (POST, PUT, DELETE, PATCH) tüm isteklerde X-XSRF-TOKEN başlığı otomatik gönderilir.
  • Proxy İletimi: api/proxy.js sunucusuz proxy fonksiyonu gelen x-xsrf-token başlığını backend kümesine kayıpsız iletir.

5.6 Altyapı Çözümleri: Vercel Serverless Proxy, K8s Dağıtımı ve Pull Request (#2)

  • Vercel CORS Proxy Mimarisi (api/proxy.js): Canlı Spring Boot backend'i yalnızca kendi alan adını kabul ettiği için Vercel'den gelen tarayıcı isteklerinde 403 Invalid CORS request dönüyordu. Vercel üzerinde çalışan özel bir Serverless Proxy yazılarak isteklerin arka planda Origin: https://kovan.universeconn.online ile iletilmesi sağlandı ve CORS engeli tamamen aşıldı.
  • Rol ve Yetkiler Panel Düzenlemesi: Kurul üyesi ata formunun kenarlara yapışması 24px padding ile çözüldü; Ata/Davet Et butonundaki boş etiket kaldırılarak buton tabana (align-items: flex-end) ve 42px yüksekliğe eşitlendi.
  • DigitalOcean K8s Test Kümesi & 4 Ekim Sürümü Nedeni: Canlı test ortamının (kovan.universeconn.online) 4 Ekim sürümünde kalmasının sebebi, k8s/overlays/cloud/kustomization.yaml dosyasında newTag: 5428d40 (4 Ekim commit'i) etiketinin tanımlı olması ve PR #2'nin birleştirilmeyi beklemesidir. Yeni derlenen Docker imajının commit SHA'si ile newTag güncellenerek kubectl apply -k k8s/overlays/cloud komutuyla test ortamı saniyeler içinde en son sürüme taşınabilir.
  • Pull Request #2: Tüm geliştirmeler BMS-144-ui dalından ekip ana dalı olan BMS-144'e GitHub üzerinden PR #2 olarak açıldı ve entegrasyona hazır hale getirildi.
